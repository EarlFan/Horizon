## [ESP32 Retrofit Replaces Costly Bowling Scoring System.](https://news.ycombinator.com/item?id=48968606) ⭐️ 7.0/10

An SRE who bought an abandoned 8-lane bowling center built a prototype replacement for its legacy scoring and lane-control system using ESP32-based hardware. The prototype costs about $200 per pair of lanes, or roughly $1,600 for the whole center, compared with an estimated $80,000 to $120,000 for a vendor replacement. The project shows how inexpensive commodity microcontrollers and open software can extend the life of niche, expensive, proprietary infrastructure. For small bowling centers and similar businesses, this kind of retrofit could reduce repair costs, avoid vendor lock-in, and make customization practical. The system uses an ESPNow star-topology mesh, with ESP32 nodes connected to relays, optocouplers, and IR break-beam sensors, plus RS485 as a wired fallback for noisy RF environments. Events are forwarded through an ESP32 gateway over UART to a Raspberry Pi lane computer, then translated into Redis-backed event streams for React, WebSocket, and pub-sub based interfaces.

hackernews · section33 · Jul 19, 14:41

**Background**: ESP32 is a family of low-cost, energy-efficient microcontrollers with integrated Wi-Fi and Bluetooth, commonly used in IoT and embedded projects. In a bowling center, the scoring system is not just a display: it can interact with sensors, detect pins or balls, trigger relays, and coordinate older mechanical pinsetting equipment. The author’s key observation is that much of the expensive proprietary system ultimately controls simple electrical interfaces to machines that are largely mechanical.

## [Moonshine adds headless hosting for Moonlight game streaming.](https://github.com/hgaiser/moonshine) ⭐️ 7.0/10

Moonshine is an open-source game streaming host that can stream PC games to Moonlight clients while creating its own compositor instead of relying on an existing desktop environment. According to the project creator, this enables headless sessions and sessions with arbitrary resolution without exposing or occupying the host’s normal desktop. This addresses a common limitation of Sunshine/Moonlight setups: the streamed game often runs visibly in the active desktop session, making the host machine inconvenient to use for other work. For self-hosted cloud gaming enthusiasts, Moonshine could make “personal GeForce Now” style setups cleaner, more isolated, and better suited to Linux or server-like environments. The key architectural difference is that Moonshine creates and controls its own compositor, which can run without a full desktop environment and can present a virtual display tailored to the client. The project appears especially relevant to users who want isolated gaming sessions, but it is still a niche systems project and should be evaluated for hardware, driver, codec, and game compatibility in each setup.

hackernews · wertyk · Jul 20, 00:16 · [Discussion](https://news.ycombinator.com/item?id=48972970)

**Background**: Moonlight is an open-source game streaming client originally associated with NVIDIA GameStream and now commonly used with open-source hosts such as Sunshine. It supports many client devices, including PCs, Macs, mobile devices, TVs, Raspberry Pi, game consoles, and other platforms, and can stream games over a home network or the internet. In this context, a compositor is the display component that combines application windows and surfaces into the final image sent to a screen or, for streaming, to an encoder and remote client.

A blog post titled “Stop Using OpenCode” criticized the OpenCode agentic coding CLI for alleged design, performance, prompt-caching, filesystem-scanning, and security issues. The post prompted an active Hacker News discussion about whether these are OpenCode-specific bugs or broader problems with AI coding agents. Agentic coding CLIs are increasingly used to read, modify, and run code inside developer environments, so inefficient context handling or weak security assumptions can directly affect productivity and risk. The critique also reflects a wider concern that AI developer tools are evolving faster than their reliability, permission, and systems-design practices. According to the discussion summary, the criticized behaviors include repeatedly globbing the filesystem, re-reading AGENTS.md, and injecting changing data such as the current date into the initial system prompt, all of which may harm prompt-cache efficiency. Commenters also noted comparisons with alternatives such as Pi and questioned whether the article should have proposed fixes rather than simply telling people to stop using OpenCode.

hackernews · alekq · Jul 20, 12:45 · [Discussion](https://news.ycombinator.com/item?id=48978112)

**Background**: OpenCode is a terminal-based AI coding tool whose documentation describes a CLI for starting its terminal user interface and managing agents with custom system prompts and permission configuration. Agentic coding CLIs differ from simple code-completion tools because they can orchestrate model calls, inspect project files, invoke tools, and sometimes make edits across a repository. Prompt caching is relevant because repeated or changing prompt content can increase latency and cost when large language models must reprocess the same context. Filesystem scanning and permission design matter because these tools often operate inside real source trees that may contain secrets, build scripts, or sensitive project context.
