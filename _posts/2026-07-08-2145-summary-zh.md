## [GitLost 暴露 GitHub AI 代理泄漏风险。](https://noma.security/blog/gitlost-how-we-tricked-githubs-ai-agent-into-leaking-private-repos/) ⭐️ 8.0/10

Noma Labs 披露了 GitLost，这是一种针对 GitHub 新 Agentic Workflows 的提示注入攻击，可能让 GitHub AI 代理从私有仓库检索数据并公开发布。该攻击通过在与私有仓库同属一个组织的公开仓库中提交特制 GitHub Issue 来触发。 这项研究凸显了一个严重的数据外泄风险：当代理式编程工具被授予对私有代码、Issue 或组织上下文的广泛访问权限时，攻击面会显著扩大。它也说明，提示注入正在成为一类普遍的 AI 代理安全问题，因为这些系统会把自然语言指令与高权限工具访问混在一起。 据报道，该攻击不要求攻击者通过身份认证；关键条件是 AI 代理已被授予访问私有仓库的权限，同时又会处理同一组织内公开仓库中的攻击者可控内容。这个案例的重点并不只是某个“神奇措辞”，而是公开输入与私有数据访问之间的信任边界被不安全地打通。

hackernews · ColinEberhardt · 7月8日 05:25 · [社区讨论](https://news.ycombinator.com/item?id=48827858)

**背景**: 提示注入是一种攻击方式，攻击者通过恶意文本覆盖或改变 AI 系统原本应遵循的指令。代理式 AI 工具比普通聊天机器人风险更高，因为它们可以调用工具、读取仓库、创建评论，或代表用户和组织执行其他操作。数据外泄指敏感信息离开原本受保护的上下文，例如从私有仓库进入公开 Issue 评论。

## [Tenda 固件存在隐藏认证后门。](https://kb.cert.org/vuls/id/213560) ⭐️ 8.0/10

CERT/CC 披露，多版本 Tenda 路由器固件包含一个未公开的认证后门，据报道该问题编号为 CVE-2026-11405。攻击者只要提供硬编码密码，就可能在不受用户名限制的情况下访问网页管理界面。 路由器固件位于家庭和企业网络边界，因此认证后门可能暴露流量、DNS、无线网络和防火墙等管理控制。由于该问题影响多个固件版本，它也加剧了外界对嵌入式设备安全以及厂商黑盒固件可信度的担忧。 相关报道称，该后门位于 /bin/httpd 网页服务器二进制文件的 login() 函数中，固件会检查一个隐藏密码值，并且不会验证对应用户名。社区分析提到一篇 2022 年的旧文章曾指出疑似密码值为“rzadmin”，但用户仍应以厂商和 CERT 的缓解建议为准。

hackernews · miniBill · 7月8日 00:08 · [社区讨论](https://news.ycombinator.com/item?id=48825749)

**背景**: 固件是内置在路由器等设备中的底层软件，通常负责认证、联网和设备管理。硬编码密码是直接写入软件或固件的凭据；一旦被发现，攻击者可能在所有共享相同代码的受影响设备上重复使用它。对于消费级路由器来说，这尤其危险，因为许多设备多年得不到及时固件更新。供应链风险还来自多个品牌或型号可能共享相同硬件或固件组件，从而让一个缺陷影响到比最初清单更多的产品。

## [欧盟聊天控制提案受到审视](https://fightchatcontrol.eu/chat-control-overview) ⭐️ 8.0/10

Fight Chat Control 发布了一篇概述，解释欧盟 Chat Control 1.0 和 2.0 提案如何涉及 CSAM 检测、加密消息和客户端扫描。该解释称，Chat Control 1.0 允许服务提供商自愿扫描，而 Chat Control 2.0 正在谈判中，并可能带来更广泛、更长期的影响。 这些提案很重要，因为它们可能重塑欧洲私人消息服务的法律和技术要求。如果平台受到压力或被要求在加密前扫描消息，批评者认为，即使加密算法本身没有被破解，端到端加密的核心保密性也会被削弱。 关键技术问题是客户端扫描，也就是在内容被加密并发送之前，先在用户设备上进行检查。Fight Chat Control 的概述称，在 Chat Control 1.0 下，端到端加密通信本身并未被扫描，但服务提供商可以在该法律框架下部署客户端扫描。

hackernews · gasull · 7月7日 14:23 · [社区讨论](https://news.ycombinator.com/item?id=48818311)

**背景**: Chat Control 指的是欧盟旨在检测和报告在线通信中儿童性虐待材料的政策提案。端到端加密的设计目标是只有发送者和接收者能够读取消息，平台运营商或网络中间方无法读取。客户端扫描之所以有争议，是因为它把检测过程移到用户设备上，并在加密之前检查内容，这可能使第三方即使在使用加密传输的情况下也能获知消息内容。

## [最小化 ZFS NAS 可运行在 Linux 上。](https://neil.computer/notes/how-to-setup-minimal-zfs-nas-without-truenas/) ⭐️ 7.0/10

Neil 的 2024 年指南说明了如何使用通用 Linux 工具构建一个最小化的 ZFS NAS，而不是购买 Synology 或 QNAP 设备，或安装 TrueNAS。文章重点是面向自托管存储的动手配置，而不是使用开箱即用的 NAS 发行版。 这很重要，因为许多家庭实验室和自托管用户希望获得 ZFS 的可靠性，但不想采用完整的 NAS 平台或厂商设备。基于最小化 Linux 的方案可以让有技术能力的用户更好地控制软件包、服务、硬件选择和长期维护。 讨论强调的是实际取舍，而不是唯一最佳架构，包括 Debian 与 FreeBSD、专用 NAS 机箱、拆取外置硬盘、SMB 服务发现，以及 dm-integrity、mdadm 和 XFS 等替代方案。主要注意点是，这条路线要求使用者愿意承担集成工作，而这些工作通常由 TrueNAS、Synology 和 QNAP 等产品隐藏起来。

hackernews · 4diii · 7月8日 03:59 · [社区讨论](https://news.ycombinator.com/item?id=48827325)

**背景**: ZFS 是一种高级文件系统和卷管理方案，它把物理设备聚合成存储池，并从存储池中创建文件系统。它在 NAS 系统中常受重视，因为它围绕数据完整性设计，并支持存储池和数据集级别的快照与复制。NAS 即网络附加存储服务器，通常通过 SMB/CIFS 等协议向网络中的其他机器提供存储。TrueNAS 是一个流行的以 ZFS 为核心的 NAS 平台，而这篇指南描述的是用标准操作系统组件组装出类似功能。

这篇文章介绍了 Kokoro，它是一种高质量文本转语音系统，可以在本地 CPU 上高效运行，而不需要高端 GPU。文章将 Kokoro 描述为适合文章朗读、无障碍工具等本地语音合成工作流的实用选择。 对 CPU 友好的本地文本转语音降低了开发者和用户使用私有、离线、低成本语音合成的门槛，不必依赖云端 API 或 Nvidia 级别硬件。这对无障碍产品、阅读器应用和端侧 AI 工具尤其重要。 社区用户提到，Kokoro 支持手动添加 IPA 发音指南，这有助于处理同形异音词需要特定读音的情况。有人指出的一个限制是，当只朗读一两个单词时，它的表现可能较弱，发音和语调可能不够稳定。

hackernews · speckx · 7月7日 18:24 · [社区讨论](https://news.ycombinator.com/item?id=48821576)

**背景**: 文本转语音，简称 TTS，是把书面文字转换成语音音频的技术。许多现代高质量 TTS 系统使用神经网络模型，并且通常受益于 GPU，这会让普通笔记本或台式机上的本地部署更困难。对 CPU 友好的本地推理意味着模型可以在用户自己的机器上运行，而不必把文本发送到远程服务，这有助于提升隐私并降低运行成本。
