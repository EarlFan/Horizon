## [Inkling targets customizable open multimodal AI.](https://thinkingmachines.ai/news/introducing-inkling/) ⭐️ 8.0/10

Thinking Machines Lab introduced Inkling, its first open-weights model, as a multimodal Mixture-of-Experts system with controllable reasoning effort and availability for fine-tuning on Tinker. Reports describe it as a 975B-parameter model with 41B active parameters that can work across text, images, and audio. Inkling is positioned less as the strongest general-purpose model and more as a base model that organizations can adapt efficiently to their own tasks. That makes it relevant to enterprises, developers, and the open-model ecosystem because customization and deployability are increasingly as important as raw benchmark performance. The notable technical combination is open weights, native multimodality, MoE architecture, audio support, controllable thinking effort, and a hosted fine-tuning path through Tinker. A key caveat is that Thinking Machines explicitly says Inkling is not the strongest overall model available today, so its value proposition depends on task-specific adaptation rather than broad frontier dominance.

hackernews · vimarsh6739 · Jul 15, 18:12 · [Discussion](https://news.ycombinator.com/item?id=48924912)

**Background**: Open-weights models publish the trained model weights so outside developers can inspect, run, adapt, or fine-tune them under the model’s license, unlike fully closed API-only systems. A multimodal model can process more than one type of input, such as text, images, and audio, which broadens the kinds of applications it can support. A Mixture-of-Experts model routes computation through selected expert submodules, so the total parameter count can be much larger than the number of parameters used for each inference. Fine-tuning is the process of further training a base model on task-specific data so it performs better for a particular organization, product, or workflow.

## [Intel starts using ASML’s High-NA EUV tool.](https://finance.yahoo.com/technology/articles/intel-begins-using-asmls-most-201109178.html) ⭐️ 8.0/10

Intel has begun using ASML’s most advanced chipmaking machine, a High-NA EUV lithography system, as part of its push to regain leadership in advanced semiconductor manufacturing. High-NA EUV is expected to help chipmakers print smaller and denser features, which is important for future leading-edge process nodes and AI hardware supply chains. Intel’s adoption could affect competition with other advanced manufacturers and the credibility of its foundry roadmap. ASML describes High-NA EUV as the next step after current EUV systems, using a higher numerical aperture to improve resolution and offering a critical dimension of about 8 nm on the EXE platform. The technology is still a major manufacturing transition, so early use does not by itself guarantee immediate high-volume production success.

openbb · AMD · Jul 15, 20:11

**Background**: EUV lithography uses extreme ultraviolet light to pattern tiny features on silicon wafers during chip manufacturing. High-NA EUV increases the numerical aperture, which is a measure of the optical system’s resolution capability, allowing even smaller structures to be imaged. ASML is the key supplier of these advanced lithography systems, making access to its newest machines strategically important for leading-edge semiconductor manufacturers.

## [Native buttons already solve hard accessibility problems](https://madcampos.dev/blog/2026/07/accessibility-from-scratch/) ⭐️ 6.0/10

Mad Campos published an article arguing that recreating basic UI controls such as buttons from scratch often removes native accessibility and usability behavior that browsers already provide. The piece frames a custom button as a deceptively complex component, not a simple visual element. This matters because frontend teams, design systems, mobile developers, and AI-generated code can easily ship controls that look right but fail for keyboard users, screen-reader users, or other assistive-technology users. It reinforces a broader accessibility lesson: prefer native semantics unless there is a strong reason to reimplement behavior carefully. Native HTML buttons already support activation by mouse, keyboard, touch, voice command, and assistive technologies, and they participate in keyboard navigation by default. The caveat is that some complex widgets, such as comboboxes with server-side filtering, may exceed what native HTML elements offer and require careful custom implementation.

hackernews · treve · Jul 16, 03:48 · [Discussion](https://news.ycombinator.com/item?id=48930136)

**Background**: HTML provides semantic elements such as button that carry built-in behavior beyond appearance. According to MDN, a button is an interactive element that can be activated through multiple input methods and is commonly used to submit forms or open dialogs. MDN’s accessibility guidance also notes that buttons have built-in keyboard accessibility, including Tab navigation and activation with Space, Return, or Enter. Replacing a native button with a generic element plus click handlers can require developers to manually recreate these behaviors.
