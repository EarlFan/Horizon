## [crustc: Rust Compiler Transpiled to C for Bootstrapping and Obscure Hardware](https://github.com/FractalFir/crustc) ⭐️ 8.0/10

The crustc project has successfully transpiled the entire Rust compiler (rustc) into C, a three-year effort that marks the 14th attempt to achieve this. The generated C code enables Rust to be compiled on platforms lacking LLVM or GCC backends and aids in compiler bootstrapping. This work opens Rust to extremely obscure or old hardware where LLVM is unavailable and addresses the bootstrapping dilemma—building rustc typically requires an existing Rust compiler. It broadens Rust's reach and could enhance trust in the compiler supply chain. The approach uses a transpiler to convert Rust source to C, then relies on GCC for optimization; the compiler implementation is not yet publicly released. The author's note about being the 14th attempt highlights the difficulty of such a translation.

hackernews · Philpax · Jul 2, 22:57 · [Discussion](https://news.ycombinator.com/item?id=48768464)

**Background**: Compiler bootstrapping is the process of building a compiler from source using a previous version of itself, creating a chicken-and-egg problem. Since the official Rust compiler is written in Rust, bootstrapping requires an existing Rust compiler; transpiling to C allows bootstrapping from a C compiler alone. Many obscure hardware platforms lack LLVM support, so a C backend provides an alternative compilation path.

## [Linux 6.9 Regression: LUKS Suspend Fails to Wipe Encryption Keys from Memory](https://mathstodon.xyz/@iblech/116769502749142438) ⭐️ 8.0/10

A kernel regression in Linux 6.9 broke the LUKS suspend feature, which previously wiped the master encryption key from RAM during suspend-to-RAM; now the key remains in memory. This regression undermines the security of disk encryption for systems that rely on LUKS suspend to protect keys during sleep, potentially allowing attackers with physical access to extract the key. The bug specifically affects the `cryptsetup luksSuspend` mechanism, often implemented via custom initramfs scripts like Debian's suspend scripts, and only impacts systems actively using this feature. A test has been added to prevent future breakage.

hackernews · IngoBlechschmid · Jul 2, 15:25 · [Discussion](https://news.ycombinator.com/item?id=48763035)

**Background**: LUKS (Linux Unified Key Setup) is the standard for disk encryption on Linux, using dm-crypt. During normal operation, the master key resides in kernel memory to decrypt data on the fly. The `luksSuspend` command temporarily deactivates an encrypted device and wipes the key from memory, reducing the window of vulnerability, e.g., before suspending the system. This feature is not universally used and is often provided by distributions like Debian via custom scripts.

## [Postgres Transactions: A Distributed Systems Superpower](https://www.dbos.dev/blog/co-locating-workflow-state-with-your-data) ⭐️ 8.0/10

The article proposes co-locating workflow state directly with application data inside Postgres, using database transactions to guarantee atomicity across workflow steps and data changes without separate message queues. This approach simplifies building reliable distributed workflows by removing the complexity of the outbox pattern and reducing potential failure points, making it easier for developers to maintain consistency between business logic and state transitions. Each workflow step becomes a single database commit unit, which inherently couples the workflow engine to the database. This tight integration may complicate future separation but offers immediate simplicity.

hackernews · KraftyOne · Jul 2, 18:38 · [Discussion](https://news.ycombinator.com/item?id=48765639)

**Background**: In distributed systems, the outbox pattern is often used to atomically update a database and send a message by writing the message to a special table within the same transaction, then relying on a separate relay process. This adds infrastructure and complexity. The article’s strategy instead lets the workflow engine directly operate on transactional state, bypassing the need for an outbox.
