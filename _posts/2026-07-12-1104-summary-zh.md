## [Mesh LLM 通过 iroh 分布式运行大模型。](https://www.iroh.computer/blog/mesh-llm) ⭐️ 7.0/10

Mesh LLM 展示了一个使用 iroh 在多台联网机器上运行大语言模型的点对点系统。该项目旨在汇集 macOS 和 Linux 设备上的消费级 GPU，并通过兼容 OpenAI 的接口提供本地或开放权重模型服务。 如果效果足够好，Mesh LLM 可能让小团队、研究人员和爱好者更容易运行超过单台消费级机器 GPU 显存容量的模型。它也反映了去中心化 AI 基础设施的趋势，即汇集本地闲置硬件，而不是只依赖集中式云端 GPU。 该项目使用 Skippy 阶段拆分把大型模型分到多个节点上运行，同时由 iroh 提供基于 QUIC 的点对点网络、 中继和打洞能力。主要限制在于性能：社区评论质疑网络带宽和延迟是否会让拆分推理慢到难以交互使用，不过有评论提到模型列表中 Qwen 235B A22B 在两个节点上达到每秒 16 个 token。

hackernews · tionis · 7月11日 22:38 · [社区讨论](https://news.ycombinator.com/item?id=48876505)

**背景**: 大语言模型在推理时需要大量 GPU 显存，因为模型参数和中间计算结果都需要被访问。模型拆分也称为模型并行，它把计算分配到多个 GPU 或节点上，使单个设备装不下的模型也能运行。iroh 是一个基于 Rust 的点对点网络库，构建在 QUIC 之上；其文档说明，节点通过 NodeId 识别，并在连接握手中提供端到端加密和身份认证。

这篇文章分析了 Nvidia 对 CoreWeave 和 Nebius 等 AI GPU 云服务商的投资，是否构成正在放大 Nvidia GPU 表观需求的循环融资。文章重点关注的风险是，Nvidia 支持的资金可能通过大规模 GPU 采购和云基础设施建设重新流回 Nvidia。 这件事很重要，因为 Nvidia 的估值以及更广泛的 AI 基础设施热潮，很大程度上取决于 GPU 需求是否具有真实的经济可持续性，而不只是由融资推动。如果云服务商过度建设算力，或无法从 AI 负载中获得足够回报，影响可能波及芯片厂商、AI 云平台、企业 AI 买家和投资者。 评论者指出，与 CoreWeave 被提到的 2026 年 350 亿美元资本开支计划相比，Nvidia 对 CoreWeave 的 20 亿美元投资规模较小，这削弱了简单将其解释为循环融资的说法。更关键的技术和经济问题包括 GPU 利用率、H100 和 A100 等较旧硬件的未来定价、按 token 计算的投资回报，以及开放权重模型是否会压低 token 价格。

## [ClickHouse 将 PgBouncer 吞吐量提升四倍。](https://clickhouse.com/blog/pgbouncer-clickhouse-managed-postgres) ⭐️ 7.0/10

ClickHouse 发布了其在 ClickHouse Managed Postgres 中将 PgBouncer 吞吐量提升四倍的方法，核心是运行多个 PgBouncer 进程并通过对等机制进行协调。该方案使用 SO_REUSEPORT 让多个进程监听同一个端口，同时保持查询取消行为的正确性。 PgBouncer 常用于降低 PostgreSQL 连接开销，但在高负载下连接池本身也可能成为吞吐瓶颈。该方案对数据库基础设施运维者很有价值，因为它展示了如何让 PgBouncer 随 CPU 核心数扩展，同时不破坏 PostgreSQL 的查询取消语义。 关键注意点是查询取消：如果取消请求到达的 PgBouncer 进程并不拥有对应客户端会话，那么在未配置对等机制时取消操作可能不会生效。PgBouncer 文档明确建议在使用多个 PgBouncer 进程时配置对等机制，相关技术文章也指出，对等支持用于解决多实例或 SO_REUSEPORT 部署中的取消请求问题。

hackernews · saisrirampur · 7月11日 15:28 · [社区讨论](https://news.ycombinator.com/item?id=48872874)

**背景**: PgBouncer 是用于 PostgreSQL 的轻量级连接池，位于应用程序和数据库之间，通过复用服务器连接来降低大量数据库会话带来的开销。SO_REUSEPORT 是一种操作系统套接字功能，允许多个进程绑定到同一个端口，从而把负载分散到多个进程上。PgBouncer 的对等机制让不同 PgBouncer 进程彼此感知，使查询取消等操作消息能够转发到真正拥有相关会话的进程。

## [应优先使用 SQLite STRICT 表](https://evanhahn.com/prefer-strict-tables-in-sqlite/) ⭐️ 7.0/10

Evan Hahn 的文章主张开发者应优先使用 SQLite STRICT 表；这是 SQLite 3.37.0 自 2021 年 11 月 27 日起提供的功能，可带来更强的类型约束。该建议旨在避免 SQLite 默认灵活类型行为导致的隐蔽数据一致性问题。 SQLite 被嵌入到许多应用中，因此列类型约束较弱可能在部署后造成难以发现的数据完整性问题。STRICT 表让团队在需要可预测模式时，可以让 SQLite 的行为更接近传统 SQL 数据库。 STRICT 是按表启用的，而不是全局启用；现有的非严格表通常需要重建或转换，而不能直接原地 ALTER 成严格表。社区讨论还指出，严格表仍有局限，例如 SQLite 支持的类型集合有限，以及可用于故意保留灵活性的 ANY 类型。

hackernews · ingve · 7月11日 17:33 · [社区讨论](https://news.ycombinator.com/item?id=48873940)

**背景**: SQLite 传统上使用动态类型系统，列声明的类型更像是一种建议，而不是绝对规则。SQLite 通过类型亲和性机制描述这种行为；它会尝试把值转换为偏好的存储类别，但并不总是拒绝不匹配的输入。STRICT 表为希望数据库引擎拒绝不符合声明列类型的值的开发者提供了更严格的模式。当一个数据库文件被多个应用或库共享，并且它们都依赖相同的模式假设时，这一点尤其重要。

## [Ant 扩展为 JavaScript 生态系统。](https://antjs.org/) ⭐️ 6.0/10

Ant 的作者在 Hacker News 上介绍了这个早期阶段的 JavaScript 生态系统，它以一个拥有自有 JavaScript 引擎的运行时为核心。该项目现在包括包管理器、ants.land 包注册表、部署和托管平台，以及用于用网页技术构建桌面应用的 Ant Desktop。 Ant 试图为当今分散的 JavaScript 工具链提供一个集成式替代方案，因为运行时、包管理、部署和桌面打包通常由不同项目分别处理。如果它成熟起来，可能会吸引那些希望获得比围绕 Node.js、Deno、Bun、npm、托管服务和类似 Electron 工具组合更小、更统一平台的开发者。 Ant 官网将该运行时描述为一个 9 MB 的单一二进制文件，支持 TypeScript、运行真实的 npm 包、具备兼容 Node 的 API、虚拟机隔离沙箱，并内置 Wasm 支持。主要限制是该项目仍处于早期阶段，因此兼容性、性能、安全性、治理方式和生态采用度都还没有得到充分验证。

hackernews · theMackabu · 7月11日 20:07 · [社区讨论](https://news.ycombinator.com/item?id=48875377)

**背景**: JavaScript 运行时是执行 JavaScript 的环境，可以在浏览器内或浏览器外运行，并提供文件、网络、进程等系统能力的 API。Node.js 让服务器端 JavaScript 成为主流，而 Deno 和 Bun 等较新的运行时则通过安全模型、性能、开发体验或包处理方式进行竞争。npm 或 ants.land 这类包注册表用于让开发者发布和发现可复用的 JavaScript 与 TypeScript 库。类似 Electron 的桌面框架允许开发者使用 JavaScript、HTML 和 CSS 等网页技术构建桌面应用。

随着外界担心未来量子计算机可能削弱当前的密码学保护，加密行业正在加强后量子安全方面的准备。此次变化更像是行业层面的风险应对，而不是某个单一技术突破。 区块链和数字资产高度依赖公钥密码学来保护钱包、签名和所有权记录，因此成功的量子攻击可能威胁用户资金和网络信任。由于迁移到量子安全系统可能需要多年时间，即使大规模量子计算机尚未出现，提前规划也很重要。 主要担忧是，足够强大的量子计算机若运行 Shor 算法等方法，可能破解基于整数分解、离散对数或椭圆曲线离散对数的常用公钥系统。目前的量子计算机尚不能破解广泛使用的密码算法，但 NIST 已在 2024 年发布首批三个后量子密码标准，供机构开始部署。

openbb · AMD · 7月11日 13:00
